# 日本語の文章スタイル

このルールは、成果物とユーザー向け報告を自然で読みやすい日本語にするための
プロジェクト方針です。プロジェクトは内容を強めたり、緩めたり、置き換えたり、
削除したりできます。削除してもSpecBindのライフサイクルや機械的な検証は変わりません。

## 基本方針

- 一般的な状態や操作の説明には日本語を使い、英単語を不用意に混ぜない。
- Spec、Requirements、Design、Contract、Tasks、Milestone、Roadmap、Gate、Steeringなど、
  SpecBindの責務を指す用語は、対応する製品概念が分かりやすくなる場合に保持する。
- 英語の専門語が必要な場合は、初出で短い日本語の説明を添え、その後は文脈に合う
  簡潔な表現を使う。
- 英単語が連続して日本語の文構造を読みにくくする場合は、単語だけを置き換えず、
  文全体を自然な語順へ書き直す。
- 見出し、表の項目名、リンクラベルも、それだけで意味が伝わる日本語にする。

## 変更しないもの

コマンド、Skill名、ファイルパス、スキーマのフィールド名、状態値、診断コード、
コードブロック、引用した出力は正確な識別子です。日本語らしさのために翻訳したり、
綴りや大文字小文字を変えたりしません。

製品概念と一般説明のどちらか判断しにくい語は、正確な英語を初出で示し、日本語で
意味を補います。機械的な一括置換ではなく、その文で何を指しているかを基準に判断します。

## 確認項目

- 日本語だけを読んで、主語、状態、操作、結果の関係を一度で理解できるか。
- 残した英語は製品概念や正確な識別子として必要か。
- 日本語化によって安全境界、所有者、停止条件を弱めていないか。
- 同じ概念を文書内で一貫した名前で表しているか。

## When to checkpoint

Whether approved planning work is committed after each gate, once at the end of
planning, or only when asked. Whether each completed implementation task gets
its own commit.

## What to include

Which paths belong in a checkpoint, and how to group related changes. Unrelated
work already in progress is left alone regardless.

## Commit messages

The form this project expects, with an example.

## Branches and pushing

Branch conventions, and whether a workflow should offer to push. Say so
explicitly if it should not.

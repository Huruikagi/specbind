# Git アダプタ

このファイルは、ワークフローのローカルなチェックポイントを定めるプロジェクト方針です。
下の節には動作する既定値が入っています。コミットの単位、メッセージ、公開方法を変えたい
プロジェクトは内容を書き換えてください。

このファイルが定めるのは方針であって権限ではありません。SpecBind が本来持たない権限を
与えることはできず、作業がコミット可能になる時点も変えられません。承認、Task完了、
リポジトリ安全性は SpecBind の契約のままです。チェックポイントに未承認、却下済み、
または無関係な作業を含めることはありません。

このファイルを空にする、または削除することは、SpecBind が自発的には何もコミット
しないという意味になります。

## いつチェックポイントするか

安全な完了単位ごとにローカルコミットを1つ作成します。完了したDiscovery、承認された
Requirements・Design・Tasksの各Gate、受理されたContract review、完了した実装Taskが
それぞれ1単位です。completionワークフローが要求する状態メタデータは別の
チェックポイントにします。

## 何を含めるか

その完了単位が作成したパスだけをstageします。worktreeにある無関係な作業はそのまま
残します。対象パスを安全に分離できない場合はコミット前に止まり、受理済みの作業が
未コミットであることを報告します。

## コミットメッセージ

プロジェクトの言語で、結果を表す簡潔な要約を書きます。識別しやすくなる場合はSpecまたは
Direct項目の名前を含めます。既定ではamend、rebase、squashなどの履歴書き換えを行わず、
後の修正は追加コミットとして記録します。

## ブランチとプッシュ

現在のブランチを使い、チェックポイントのためだけにブランチを作成または切り替えません。
現在の実行についてユーザーが明示的に依頼した場合、または適用対象のプロジェクト指示が
別途要求する場合を除きpushしません。force-pushや保護ブランチの迂回は行いません。

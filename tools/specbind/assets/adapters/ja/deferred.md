# 保留指摘アダプタ

このファイルは、実在するがゲートを止める理由にはならないレビュー指摘をどこに
残すかを定めるプロジェクト方針です。下の節には動作する既定値が入っています。
課題管理システムなど既存の置き場がある場合は、その行き先へ書き換えてください。

行き先は書き込む場所であって、読む場所ではありません。ここに置かれただけで作業に
なる項目はなく、人が Roadmap に追加したときだけ通常のスコープ判定へ戻ります。

## 保留指摘の行き先

構成済みSpecBindルートの `deferred.md` に追記します。既定の `specDir` では
プロジェクト相対パスは `.specbind/deferred.md` です。これは全Specで共有する1つの
ファイルです。

ファイルがなければ、次の内容で作成してから最初の指摘を追記します。

```markdown
---
type: Deferred Findings
---

# Deferred findings
```

指摘ごとに1エントリを書き、どの Spec から出たかと何を危うくするかを記し、それ
以外は書き加えません。このファイルはOKF conceptですが、SpecBindの成果物、ゲート、
fingerprint、または作業キューではありません。

追記の前に、同じ指摘が既に記録されていないかを確認できる範囲でだけ読み、記録済
みであれば追記しません。それ以外の目的で内容を使わないでください。

## ここに置くもの

実行可能で残す価値があり、かつ verdict を変えない観察。verdict を変える指摘は
ゲートの前に解消するものであって、ここには記録しません。

## ここに置かないもの

今回の変更が行わなければならない作業、判断を止めている未解決の問い、そして
それを生んだレビュー以外に読み手のいない覚え書き。

# バグ報告と改善提案

SpecBindのCLI、製品管理のスキル、Agent連携、インストール済みファイル、
ドキュメントに問題があるときや、ワークフローを改善したいときは、GitHubの
Issue Formから報告できます。CLIで入口を確認するには、プロジェクトの外でも
次を実行できます。

```console
specbind feedback
```

このコマンドは、バグ報告と改善提案それぞれのフォームURL、報告に含める情報、
公開前の注意を表示します。ブラウザを開かず、ネットワークへ接続せず、環境情報や
プロジェクト内容を収集・送信しません。

## バグを報告する

[Bug report / バグ報告](https://github.com/Huruikagi/specbind/issues/new?template=bug-report.yml)
では、次の情報を入力します。

- 問題の概要
- `specbind --version`の出力全体
- 問題がある領域
- OS・実行環境、インストール方法、関係するAgentやクライアントとそのバージョン
- 関係するCLIコマンド、スキル、またはインストール済みファイル
- 最小限の再現手順
- 期待した結果と実際の結果
- 診断コードを含むCLI出力、生成された成果物、Git差分などの観測可能な証拠

スキルの問題では、機密情報を除去した元の依頼も再現手順へ含めます。どのスキルが
関係するか判断できない場合は、関連するコマンドまたはスキル欄に`unknown`と記載
できます。

再現に必要な情報を残しつつ、アクセストークン、利用者名、非公開リポジトリ名、
ローカルパス、Specや成果物の非公開内容は伏せてください。出力をそのまま公開して
よいか、各行を確認してから送信します。

## 改善を提案する

[Improvement proposal / 改善提案](https://github.com/Huruikagi/specbind/issues/new?template=improvement.yml)
では、対象領域、現在困っていること、対象ワークフロー、望ましい結果を入力します。
対象領域にはCLI、製品管理のスキルやオーケストレーション、Agent連携、成果物、
ドキュメントなどを選べます。

具体的なコマンドや実装案がなくても提案できます。まず問題と利用場面を説明し、
提案する振る舞いや現在の回避策がある場合だけ任意欄へ記載してください。

## どちらにも当てはまらない場合

GitHubではblank Issueも利用できます。ただし、再現可能な不具合にはバグ報告、
製品やワークフローの変更案には改善提案のFormを使うと、確認に必要な情報を
揃えやすくなります。
